# MACC 网站维护说明

当前默认页面：C-V3。更新日期：2026-10-03。

会议要求的页面修改已统一接入七个版本。缺少的资料使用示例，不能当成团队正式资料。C-V3 中心图形保持不变，滚动时固定、接近页脚渐隐；MACC 缩小进入导航栏的动效已恢复。

## 1. 日常维护入口

日常文字资料统一放在 `content/` 目录，七个版本和默认首页共用，不必逐个修改 HTML。原来的 `scripts/content.js` 现在只是程序读取入口，**不再在那里填写资料**。

| 文件 | 用途 |
| --- | --- |
| `content/publications.js` | 手动维护全部论文及引用，网站按发表日期选取最新 15 条 |
| `content/site.js` | 团队、导航、新闻、成员、项目、应用系统、获奖、联系方式 |
| `assets/portraits/` | 成员透明 PNG 头像 |
| `assets/papers/`（需要时自行新建） | 可以公开的论文 PDF，链接写成 `./assets/papers/文件名.pdf` |
| `site.config.json` | 默认中心方案 |

`content/site.js` 中各字段的用途：

- `team`：中英文名称、研究方向、介绍、招生。
- `navigation`：导航及正文的共同顺序。
- `news`：全部新闻，不再截取前十条，不需要配置分页。
- `memberGroups`、`members`：分组、配色及成员。
- `projects`、`patents`、`awards`：项目、应用系统、获奖，保留现有形式，数组可以继续追加。
- `contact`：底部联系信息及可选备案文字。

**最快的论文更新流程：** 打开 `content/publications.js`，在数组中追加一篇完整对象，填写 `date` 和内容；运行 `npm run check:content` 检查，刷新本地预览；确认后提交并推送，按第 10 节手动发布。无需手工挑选 15 篇，也无需删掉较早论文。

这些文件是 JavaScript 数据文件，可以写 `// 注释`，不是 Word 或 Excel。保留文件开头的 `export const ... =` 和结尾的 `];` / `};`；相邻对象之间要有逗号，文字使用英文引号。双引号内出现双引号时写成 `\"`，多行 BibTeX 使用反引号。中文内容请以 UTF-8 保存。

`content/` 中的全部资料和 `assets/` 会随网站公开，包括不在最新 15 条内的旧论文；这里不能存密码、密钥、未公开论文或内部个人资料。未准备发布的草稿不要加入这份清单。共享视觉样式仍位于 `styles/client-refinements.css`，日常换文字不必修改。

修改后刷新本地页面；线上网站还需要重新发布。`index.html` 和七个方案 HTML 是生成文件，日常不直接修改，重新导入会覆盖。

## 2. 导航与正文一起排序

在 `navigation` 中移动完整对象即可，例如：

```js
navigation: [
  { id: "home", label: "Home" },
  { id: "publications", label: "Publications" },
  { id: "members", label: "Members" },
  { id: "projects", label: "Projects" },
  { id: "patents", label: "Systems" },
  { id: "awards", label: "Awards" }
],
```

这会把 Publications 的菜单和正文一起移到 Members 前面，Section 编号、滚动高亮和点击定位同步调整。

1. Home 固定首位，确保首页和动效关系不变。
2. 只改位置，不改 `id`。Systems 的内部 ID 仍是 `patents`。
3. `label` 只改菜单文字，不会自动改正文标题。
4. 重复 ID 会忽略，未知 ID 不会生成无效入口。
5. 删除导航项只移除菜单入口，正文保留在已配置区块之后。
6. 页头、页脚不参与排序。全新栏目需要同步开发结构，不能只添加未知 ID。

支持的 ID：home、members、publications、projects、patents、awards。

## 3. 切换中心方案

```powershell
npm run select:concept -- A-V2
npm run select:concept -- C-V3
```

可选 A-V1、A-V2、A-V3、B-V3、C-V1、C-V2、C-V3。命令更新默认首页和配置，不改变共享数据，不需要原反馈包。直接修改 `site.config.json` 后运行 `npm run select:concept` 也可生效。

七个版本都包含新闻滚动、成员分组、招生、联系栏和引用功能。切换后仍应在常用窗口检查首屏构图；C-V3 的位移及圆环修复只作用于 C-V3。

## 4. 首页与招生

首页采用灰色英文团队名、白色中文标题、蓝色研究方向短语、短介绍和招生句。

首屏以中文主标题为主要视觉入口：标题字号和占幅更大，向中心图形左侧留白延展；新闻作为次要信息，缩小标题并错开高度，不追求左右对称。桌面 Logo 与英文团队名并排，不单独占一行，下滑缩入导航的动效仍保留。C-V1、C-V2 保留原方案新闻在下方的构图，较窄窗口也将新闻放到下一行，手机仍使用导航中的 Logo。

研究方向保留分点语义，横向紧凑排列并按空间换行。新闻保持纵向滚动和全部条目，日期、标题和来源均保留；去除两侧生硬的装饰性分隔，使文字与图形共用完整背景。相关样式集中在 `styles/client-refinements.css`，七个版本共享，不改变成员分组、引用功能、中心动画绘制、固定滚动与页脚渐隐逻辑或页脚动画。替换正式标题后应检查桌面和手机的换行效果。

首页底部的三项点色图例已移除，暂停动效按钮保留并靠右。首页高度随内容展开，并缩短进入下一节前的留白；不改变中心图形的几何尺寸和绘制逻辑。重新导入概念方案或构建静态页面时同样会移除旧图例。

章节原有短线与新闻标记采用统一的三节点图案，资源位于 `assets/topology-mark.svg`。新闻链接、论文链接与 Cite 按钮在鼠标悬停或键盘聚焦时显示金色节点及短线；无链接的文字不增加可点击暗示，论文卡片悬停时不再上移。没有增加背景颗粒，也没有更改 MACC Logo 或中心图形结构。

首次进入首页时，中心图形以低亮度呈现，文字与字体就绪后整体淡入，新闻稍后显现。正常入场约半秒，快速加载时先留约 180 毫秒的准备时间；等待上限为 1.8 秒，到时直接显示已有文字。滚动、触摸、点击或键盘操作会立即结束入场。直接进入正文锚点、浏览器返回恢复页面和系统“减少动态效果”模式不重复播放。

首页标题、研究方向、介绍、招生、新闻和导航已预先写入 HTML，避免主脚本加载较慢时只出现中心图形。正式发布运行 `npm run build:site` 时，会自动从 `content/site.js` 重新生成这些内容，仍只需维护这份数据。主脚本加载失败时，首页静态文字和新闻仍可阅读；这不是整站离线功能。

本地修改内容后，通常刷新即可看到主脚本更新；如需同步检查慢加载或禁用脚本时的首屏，先运行 `npm run build:hero` 更新八个入口的静态副本。不要直接修改 HTML 中生成的首页文字。入场状态与超时配置位于 `tools/prerender-homepage.mjs`，修改后同样运行 `npm run build:hero`；字体就绪后的触发在 `scripts/app.js`，样式在 `styles/client-refinements.css`。可运行 `npm run test:presentation` 验证加载与交互。

```js
team: {
  titleLines: ["多智能体认知", "与协同团队"],
  englishName: "Multi-Agent Cognition and Collaboration Team",
  researchDirections: ["多智能体系统", "认知与推理", "协同智能"],
  summary: "团队介绍文字",
```

`titleLines` 每项是一行；研究方向建议 3-4 项。`acronym` 维护 MACC 缩写，`markLabel` 维护导航栏标识。页脚团队名和介绍自动复用 team，不必重复修改。

`recruitment.text` 留空时整句不显示；`href` 留空则显示纯文字。目前招生句是示例，点击前往底部联系栏。

## 5. 新闻

按 `news` 数组顺序展示所有条目，默认建议最新在前。保留 date、title、source、href 字段；source 和 href 可不填。

新闻区域固定可视高度，鼠标滚轮、触屏和键盘可纵向浏览。没有 Prev/Next，滚到边缘后可继续滚动主页面，不拦截整页滚轮。空数组会显示暂无新闻状态。

## 6. 成员与透明 PNG

三个独立分组默认依次为 Teachers、Collaborators、Students。桌面每行四人，窄屏每行两人，极窄屏一人；保留角标及两字母缩写。

同组超过四人时自动向下追加行，例如九位教师在桌面排为 4 + 4 + 1；这一组全部显示完才开始下一组，不分页、不隐藏成员。只需继续往 `members` 添加对象。

```js
memberGroups: [
  { id: "teachers", label: "Teachers", color: "#b7d7bd" },
  { id: "collaborators", label: "Collaborators", color: "#dccb9d" },
  { id: "students", label: "Students", color: "#b4ccdf" }
],
members: [
  {
    name: "Lin Chen",
    initials: "LC",
    group: "teachers",
    role: "Professor",
    image: "./assets/portraits/lin-chen.png",
    portraitPosition: "50% 100%",
    bio: "研究方向短介绍。",
    href: ""
  }
]
```

- 修改 group 的 label 可用中文；调整 memberGroups 顺序即可调整分组先后。
- 成员的 group 对应分组 id。同组统一底色，不再从个人照片取色；只改分组 color 即可统一调整。
- 将正式透明 PNG 放入 `assets/portraits/`，填写对应 image 路径。不要使用带白底的 JPG 冒充抠图。
- 头像采用 contain 完整显示，不按封面图裁脸。缺失或加载失败时保留组色与缩写，不显示破图。
- 未配置的分组仍会保留成员并追加显示，避免因填写错误静默丢人；正式维护应核对 group 拼写。
- 空组显示待更新状态。长姓名、职位和介绍允许换行。
- 当前 12 个名字均为虚构示例，使用同一张生成透明样张比较三种底色，不是实际成员名单。
- 更换全部正式资料后，清空 `membersNotice` 可移除示例声明。

样张及生成提示词记录在 `assets/portraits/README.md`。

## 7. 论文简介与引用

### 完整清单与最新 15 条

只维护 `content/publications.js` 中的 `publications` 数组，它是完整论文总表，可以持续追加；**不是只填写 15 条，也不是抓取 Google Scholar 或其他外部平台**。

1. 页面读取整个总表，按 `date` 从新到旧排序，再显示前 15 条。第 16 条及更早的论文仍保留在文件中，不分页、不自动删除。
2. 不足 15 条时显示全部；空数组 `[]` 显示暂无论文。当前只有 7 条演示论文，因此页面仍显示 7 条，不会复制示例凑数。
3. `date` 必填，推荐 `"2026-10-03"`；也支持只知道年月时的 `"2026-10"`，或只知道年份时的 `"2026"`。月份和日期必须两位，不能用斜杠或中文日期。
4. 只填年时按该年 1 月 1 日排序，只填年月时按该月 1 日排序；同一排序日期按文件中原有先后排列。若要精确区分同年论文的新旧，请补齐已核实的日期，不要编造日期。
5. 排序只看 `date`，不看添加位置、文件修改时间或 `meta` 中写的年份。编辑旧论文的简介不会使它自动变成最新论文。
6. `date` 是发表日期，不是定时上线日期；填写未来日期也会立即参与排序。仅把已经可以公开的资料放进总表。
7. 同一篇论文只保留一个对象。修改时编辑原对象，不要重复追加；网站不自动合并重名条目。
8. Cite 按钮与排序后的论文绑定，GB/T 7714 和 BibTeX 不会因顺序变化串到别的论文。

当前示例的 `date` 只沿用旧页面已有年份，未核实真实发表日期；正式交接时请统一按照已核实的在线发表日期或正式刊发日期填写，避免混用口径。

例如：清单中有 23 篇时只显示最新 15 篇；在文件末尾新增一篇日期最新的论文，它会自动成为页面第一篇，原第 15 篇退出页面，但仍留在总表里。

### 新增一篇论文

Publications 标题保持正体和完整文字，不加序号，宽度约占右侧内容区的 60%；下方 summary 保持斜体和紧凑行距，宽度约占该内容区的 80%。手机窄屏两者使用全部可用宽度，避免过度换行。Systems 不受影响。

在 `export const publications = [` 与结尾 `];` 之间追加以下对象。下面是填写模板，不是真实论文，替换后再保存；上一对象与新对象之间保留逗号：

```js
{
  date: "2026-10-03",
  title: "Paper title",
  meta: "2026 / Journal Article / Journal Name",
  summary: "Paper summary.",
  href: "",
  citationExample: false,
  citations: {
    gbt7714: "核实过的 GB/T 7714 文本",
    bibtex: `完整 BibTeX 条目`
  }
},
```

`date`、非空的 `title` 必填。`meta` 是左侧年份/类型/期刊文字，`summary` 是右侧斜体介绍，均为纯文字，不填写 HTML 标签。它们不会根据 `date` 或标题自动生成，修改日期时请同步核对 `meta`。`href` 可填正式论文 URL 或公开 PDF 的相对路径，留空时标题不跳转。`summary`、`meta`、`href` 暂无资料时可留空或省略。

Cite 弹窗仅显示 GB/T 7714 和 BibTeX，均支持预览和复制；MLA、APA 与底部四个下载链接已移除。旧数据中的其他格式字段可以保留，但不会显示。只出现已有数据的格式；复制成功有提示，权限被拒绝时选中文本以便手动复制。关闭图标、遮罩和 Escape 均可关闭，焦点回到原按钮。

**现有 7 条演示论文明确设置了 `citationExample: true`，因此缺少 citations 时才生成带 EXAMPLE ONLY 标记的示例引用。** 作者、期刊等是占位元数据，弹窗有警示，复制也保留警示，不可用于学术引用。逻辑在 `scripts/citation-examples.js`。

正式替换时填写该论文自己的 citations，并设 `citationExample: false`。新论文省略 citations 且不设置示例标记时，不会自动编造引用；也可以显式填 `citations: {}`，弹窗显示“数据尚未提供”。只掌握一种格式时仅填该项。不要把其他论文的引用复制过来。网站不自动校验作者、卷期、页码，也不转换正式引用格式。

### 检查与排错

```powershell
npm run check:content
```

检查会列出论文总数、页面显示数量和最终显示顺序。它检查论文标题、真实日历日期、链接类型及引用字段的格式，包含第 16 条之后的历史记录，不验证论文的学术真实性。错误示例 `publications[3] (entry 4).date` 表示总文件中第 4 个对象的日期有问题。

日期缺失、`2026-02-30`、把文字字段写成数字、引号或逗号漏写等应修正后再发布。`npm run build:site` 和 GitHub 发布构建会检查论文资料，遇到格式错误停止构建，不替换现有线上版本。本地预览时，字段不合格的论文会被略过并在控制台提示；若 JavaScript 语法本身错误，则可能影响其他动态内容加载，因此不要只靠浏览器目测判断。

### 获奖装饰

获奖卡片右上角使用穗花/月桂环装饰，资源为 `assets/award-laurel.svg`，金属色与浮雕层次由 `styles/client-refinements.css` 设置。它是装饰而非按钮，不增加点击操作；卡片原有背景质感保留，标题及元信息为纹样预留空间。

## 8. 底部联系栏与备案

```js
contact: {
  isExample: false,
  email: "正式邮箱",
  phone: "正式电话",
  office: "正式办公室地址",
  filing: { text: "", href: "" }
}
```

桌面三项横排，手机纵排；长邮箱、地址自动换行。邮箱可点击，正式电话可拨号；示例电话不会生成拨号链接。空字段不显示。

当前邮箱使用示例域名、电话使用全零占位、办公室标记为示例，`isExample: true` 会显示说明。正式资料填好后改为 false。备案文字留空时不显示；按实际部署需要填写文字及链接，本项目不代为判断备案要求。页脚年份自动更新。

页脚光带已升级为 Three.js 三维交织曲面，使用青绿、珍珠白和少量香槟金。移除了深黑色边缘遮罩，画布及边缘保持透明，与页脚底色自然融合。桌面支持轻微鼠标视差，节点与连接保持固定拓扑，曲面按有界函数起伏，不会随时间持续变形散开。

实现位于 `scripts/footer-field.js`，外观位于 `styles/client-refinements.css`。Three.js 资源保存在 `assets/vendor/three/`，不依赖外部 CDN。窗口与父容器尺寸监听会重新计算全宽和画布分辨率。手机与桌面均持续运动，小屏（宽度不超过 760px）目标帧率为 30 帧，较宽窗口为 40 帧；节点数量随宽度减少，画布像素比上限为 1.5。离开页脚视口或切换到后台时暂停，返回后继续；系统开启“减少动态效果”时保持静态。WebGL 不可用时自动降级为透明的静态点线网络。

首次加载已优化：浏览器只请求一个精简后的 `footer-runtime.min.js`，未计传输压缩的文件体积从约 2.1 MB 降至约 535 KB。首页入场结束、页面加载完成后，在浏览器空闲时间提前下载并绘制首帧；距页脚约 1600px 时也会触发准备。页脚不在视野中时不持续播放，不会让后台动画一直占用资源。

下载期间先显示无需额外资源的轻量点线预览，复用三维光带的节点、颜色与相机投影。完整三维首帧绘制成功后，再短暂交叠过渡；下载失败时保留静态预览。支持省流量或 2G 网络提示的浏览器不进行全页空闲预热，仍在接近页脚时加载。实际等待时间取决于网络与设备，优化不保证所有环境都瞬间启动。

正式构建 `npm run build:site` 会自动生成精简运行文件。本地升级 Three.js 原始资源后运行 `npm run build:footer`；不需要为了修改新闻或团队资料重新制作动效。性能与视觉回归命令为 `npm run test:footer`，覆盖慢加载、下载失败、省流量、透明边缘、窗口连续缩放及长时间运动。

## 10. GitHub Pages 发布

页面的 HTML、CSS、JavaScript 和 Canvas 动效可通过静态网站方式托管；浏览器负责动效运行。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

```powershell
npm run build:site
```

命令先检查完整论文总表，再在 artifacts/site-随机后缀 下生成全新的部署目录，只复制网站页面、content、scripts、styles、assets 和 .nojekyll，不包含 node_modules、交接文档、会议记录、原始反馈包或工作截图。默认首页以 site.config.json 为准；部署包使用相对路径，支持仓库子路径。

已提供 `.github/workflows/pages.yml`，采用手动发布，避免修改示例时自动公开：

1. 将更新提交并推送到公开仓库 [Brooks-SUN/Brooks-SUN.github.io](https://github.com/Brooks-SUN/Brooks-SUN.github.io)。发布仓库使用 `main` 分支。
2. 在仓库 Settings > Pages 中选择 GitHub Actions 作为发布来源。
3. 在 Actions 中找到 Publish Website，选择 Run workflow。
4. 完成后使用 github-pages 环境给出的地址检查资源、导航、引用复制、MACC 入位与中心/页脚动效。
5. 后续更新内容、提交后，再手动运行发布工作流。

发布成功后的默认地址为 https://brooks-sun.github.io/ 。七个版本共用一个站点，分别在这个地址后加 `A-V1.html`、`A-V2.html`、`A-V3.html`、`B-V3.html`、`C-V1.html`、`C-V2.html`、`C-V3.html`；首页默认使用 C-V3。

日常更新时先提交、推送代码，再运行 Publish Website。只推送不会自动修改线上页面。切换默认版本时运行 `npm run select:concept -- 方案名称`，将 `index.html` 和 `site.config.json` 一起提交，再发布即可。GitHub 网页中只修改 `site.config.json` 并提交后发布，也会在构建时选择正确的默认首页。

也可以不在本地编辑：在 GitHub 仓库中打开 `content/publications.js` 或 `content/site.js`，使用编辑按钮填写并提交到 `main`，再手动运行 Publish Website。正式发布前仍建议在本地预览排版。若 Actions 的构建失败，打开失败步骤查看出错字段，修正后重新运行；不用改部署目录内的文件。

发布流程基于 [GitHub 官方自定义工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。本地已提供部署包的子路径浏览器检查，但不以本地通过冒充线上验收。发布是否成功以 Actions 中的工作流结果及实际线上访问为准。

## 12. 部署到甲方的 GitHub 账号

不需要甲方提供账号密码、短信验证码、恢复码或个人访问令牌（PAT）。推荐由甲方持有仓库，开发者使用自己的 GitHub 账号，通过仓库协作权限完成交付。

### 甲方需要提供或操作的事项

1. 提供 GitHub 用户名（或团队组织名）、目标仓库地址，以及希望使用的网址。
2. 用自己的账号创建公开仓库；GitHub Free 可使用公开仓库发布 Pages。若希望网址为 `https://用户名.github.io/`，仓库必须命名为 `用户名.github.io`；若仓库叫 `macc-lab`，默认网址则为 `https://用户名.github.io/macc-lab/`。根站点每个账号只有一个，如果已经有个人主页，不要直接覆盖，应先确认是否采用项目子路径。[GitHub Pages 站点类型](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)
3. 在仓库 Settings > Collaborators > Add people 中邀请开发者账号（当前为 `Ex1st-hash`），开发者接受邀请后即可协作。组织仓库可授予该仓库的 Write 权限，不必共享整个组织的管理权限。[邀请协作者](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository)
4. 由仓库所有者或具备相应管理权限的人在 Settings > Pages > Build and deployment > Source 选择 GitHub Actions；若组织限制了 Actions 或部署环境，还需要管理员允许本仓库使用相应工作流。普通写入权限不等于可以修改 Pages 设置。[配置发布来源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

### 开发与发布交接

开发者确认目标仓库后推送已审核的代码，包括 `.github/workflows/pages.yml` 和 `content/`。新仓库的工作流应位于其默认分支，再在 Actions > Publish Website > Run workflow 选择正确分支发布；具有仓库写入权限的人可以手动运行工作流。若部署环境要求审批，则由指定审批人放行。[手动运行工作流](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)

本项目工作流已声明部署所需的 `pages: write`、`id-token: write` 权限，无需额外把甲方 PAT 配置为发布密钥。甲方账号的登录与开发者账号的推送认证各自完成，不在聊天、源码或交接文档中保存任何凭证。[Pages 工作流权限](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

迁移后检查默认首页和七个方案、头像与图形资源、导航、论文排序和引用复制，并更新 README 与本说明中的仓库及站点地址。完成交接后，甲方可保留或撤销开发者的协作权限；网站和源代码仍归甲方账号管理。
